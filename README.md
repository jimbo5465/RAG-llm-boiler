# RAG LLM آرشیو دانش فنی نیروگاه فردوسی

به‌روزرسانی مستندات: ۲۰۲۶/۱۰/۰۶

این پروژه مکاتبات فنی و پیوست‌های آن‌ها را به متن قابل ردیابی تبدیل می‌کند، بسته‌های منبع برای NotebookLM می‌سازد و پس از استخراج درس‌آموخته یا پیشنهاد فنی، اصل مدارک مورد استناد را کنار گزارش Word جمع‌آوری می‌کند. پردازش محلی برای CPU طراحی شده است؛ OCR منتخب از Google Drive استفاده می‌کند. استخراج دانش در گردش کار فعلی توسط کاربر در NotebookLM/Gemini انجام می‌شود و به این برنامه اتصال خودکار ندارد.

## گردش کار روزمره

| مرحله | فایل دابل‌کلیک در ریشه | ورودی | خروجی |
| --- | --- | --- | --- |
| تبدیل ایمیل | `Run_MSG_Extractor.bat` | پوشه MSG و ریشه خروجی دلخواه | مجموعه ایمیل، اصل پیوست، متن و گزارش‌ها |
| بسته‌بندی منابع | `Run_NotebookLM_Bundler.bat` | پوشه مجموعه تبدیل‌شده و ریشه بسته‌ها | یک یا چند Markdown و `bundle_manifest.json` |
| استخراج دانش | استفاده کاربر از NotebookLM/Gemini | Markdownهای بسته | گزارش Word با شناسه‌های منابع |
| جمع‌آوری شواهد | `Run_Knowledge_Collector.bat` | گزارش‌ها، مانیفست، آرشیو و مقصد دلخواه | پوشه هر موضوع شامل Word و اصل PDF/Excel/Word/MSG |

`Run_Outlook_Extractor.bat` مسیر خط فرمان قبلی برای MSG است؛ با وجود نام آن نصب Outlook لازم نیست. این فایل OCR و RAG را فعال می‌کند و با برنامه پنجره‌ای جدید که Embedding نمی‌سازد تفاوت دارد. اتصال مستقیم به Outlook کلاسیک نیز در `src/app_gui.py` حفظ شده است؛ جزئیات در [راهنمای Outlook](docs/OUTLOOK_GUI_WORKFLOW_FA.md).

برای ورود ایمیل جدید به انتخاب مسیر `final` وابسته نیستید. نام پوشه مجموعه در استخراج و بسته‌بندی جدید از نام پوشه ورودی گرفته می‌شود. بسته و مانیفست همان مجموعه باید با هم نگهداری شوند؛ تغییر مسیر و ساخت مجدد بسته می‌تواند شناسه ایمیل را تغییر دهد.

## نصب و اجرای خط فرمان

Python 3.10 یا بالاتر و CMD ویندوز لازم است. از ریشه پروژه:

```bat
set PYTHONIOENCODING=utf-8
py -3 -m pip install -r requirements.txt
```

برای OCR، تنظیم OAuth و توکن محلی گوگل لازم است. RAR به `rarfile` و ابزار UnRAR نیاز دارد؛ کتابخانه به‌تنهایی جای ابزار بازکردن آرشیو نیست. مسیر MSG به Outlook نیاز ندارد؛ اتصال مستقیم Outlook به Outlook کلاسیک و `pywin32` وابسته است.

```bat
set PYTHONIOENCODING=utf-8
py -3 src/msg_folder_runner.py --input "D:\Archive\boiler" --output-root "E:\Knowledge"
py -3 src/notebooklm_folder_runner.py --input "E:\Knowledge\boiler" --output-root "E:\Bundles"
```

این مسیرها نمونه‌اند. خروجی هم‌نام استخراج یا بسته‌بندی بازنویسی نمی‌شود. برای راهنمای گزینه‌های هر ابزار از `--help` استفاده کنید.

## اصل مدارک و ردیابی

`attachment_manifest.json` ارتباط فایل خام با ایمیل‌های والد را نگه می‌دارد. `bundle_manifest.json` شناسه‌های `E-...` و `A-...-T-...` را به منابع همان بسته وصل می‌کند. `pipeline_summary.json` مسیر ورودی MSG و نتیجه اجرا را ثبت می‌کند. گزارش‌های کیفیت وضعیت تبدیل و پوشش را نشان می‌دهند؛ جای مانیفست شناسه‌ها را نمی‌گیرند.

جمع‌آوری مدارک از Markdown فقط به‌عنوان واسطه ردیابی استفاده می‌کند. تحویل نهایی اصل فایل‌های مرجع است؛ ZIP ساخته نمی‌شود. ایمیل‌های ارجاع‌شده و ضمائم آن‌ها جمع‌آوری، فایل‌های کاملاً یکسان یکتا و کپی‌ها با هش کنترل می‌شوند. گزارش بدون تغییر دوباره کپی نمی‌شود؛ گزارش تغییرکرده در پوشه شماره‌دار جدید می‌آید. منابع مفقود و اختلاف نسخه‌ها در نتیجه اعلام می‌شوند.

## ساختار ریپازیتوری

```text
src/          کد استخراج، OCR، RAG و سه برنامه پنجره‌ای
tests/        آزمون‌های خودکار
tools/        ابزارهای بررسی، اجرای مجموعه و بازیابی
docs/         راهنماها، گزارش‌های فنی و سند مبنا
packaging/    تنظیمات ساخت فایل اجرایی
```

در ریشه، README، AGENTS، requirements و فایل‌های BAT باقی مانده‌اند. مسیر داده‌های محلی شامل `test_inputs/`، `Extracted_Data/`، خروجی‌های قدیمی `Extracted_Sample/` و گزارش‌های دانش است. کد از ریشه مشترک `src/project_paths.py` برای تنظیم پیش‌فرض‌ها استفاده می‌کند. مسیرهای داده‌های موجود هنگام سازماندهی تغییر نکرده‌اند.

## وضعیت RAG و کیفیت

`src/step4_rag.py` چانک‌بندی، Embedding چندزبانه و جستجوی معنایی با ChromaDB را پیاده‌سازی می‌کند. نتیجه فعلی آن قطعات مرتبط با متادیتای منبع است؛ تولید خودکار پاسخ تحلیلی یا استخراج نظام‌مند درس‌آموخته در این فایل پیاده‌سازی نشده است. نصب اختیاری:

```bat
set PYTHONIOENCODING=utf-8
py -3 -m pip install chromadb sentence-transformers
py -3 src/step4_rag.py --dataset-dir "Extracted_Data\dataset" --index
```

این دستور برای مجموعه موجود نمونه است. گزارش اجراهای تاریخی first/second/third/final، RAG را غیرفعال ثبت کرده‌اند. وجود کد RAG به‌تنهایی اثبات ساخت ایندکس یا کیفیت پاسخ نیست.

PDF صفحه‌به‌صفحه بررسی می‌شود؛ متن محلی سالم حفظ و صفحات مشکوک برای OCR ارسال می‌شوند. اگر سند بیش از ۱۵ صفحه یا بیش از ۱۰ مگابایت باشد، پنج صفحه نخست پردازش می‌شود. کیفیت معمول رندر ۳۰۰ DPI است. دست‌نویس فارسی و جدول‌ها همچنان محدودیت دارند؛ کنترل سلامت متن، صحت معنایی اعداد و روابط را تضمین نمی‌کند. Excel سقف فعلی ۱۰۰۰ سطر و ۴۰ ستون در هر شیت دارد.

## آزمون و نگهداری

```bat
set PYTHONIOENCODING=utf-8
py -3 -m unittest discover -s tests
```

این دستور راه اجرای آزمون‌هاست و به معنی اجرای موفق تازه همه آزمون‌ها در این بازبینی مستندات نیست. برخی ابزارهای `tools/` روی اسناد نمونه کار می‌کنند و ممکن است OCR واقعی انجام دهند؛ آزمون‌های واحد را با اجرای واقعی آرشیو اشتباه نگیرید.

اسکریپت‌های آزمایش یک‌باره حذف و کد، آزمون‌ها و مستندات سازماندهی شده‌اند. اصل ایمیل و مدارک حذف نشده‌اند. فایل‌های اطلاعات ورود و خروجی‌های خصوصی نباید در Git ثبت شوند؛ انتخاب مسیر خارجی توسط برنامه به معنی اضافه‌شدن آن مسیر به `.gitignore` نیست.

سند مبنا [نسخه ۰٫۱ تعریف مسئله](docs/سند%20تعریف%20مسئله.docx) برای حفظ سابقه تغییر نکرده است؛ وضعیت اجرایی فعلی در این README و راهنماهای تاریخ‌دار ثبت می‌شود.
