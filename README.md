# RAG-LLM — آرشیو دانش ایمیلی بویلر نیروگاه فردوسی

> **هدف:** تبدیل آرشیو ایمیل‌های کاری (۱۰۰ پیام از پوشه `بویلر واحد ۳`) به منبع دانش قابل جستجو برای هوش مصنوعی — با **هزینه صفر، بدون سخت‌افزار جدید، و پشتیبانی کامل از فارسی**.

سند مبنا: [`سند تعریف مسئله.docx`](سند%20تعریف%20مسئله.docx) — نسخه 0.1

---

## ۱. صورت مسئله

در طول سال‌ها حجم قابل توجهی دانش ضمنی در مکاتبات، گزارش‌ها و مستندات پراکنده شده:

- ایمیل‌های فنی (کسری متریال، MTO، WPS/WPQ، NDT، رنگ، عایق)
- تاریخچه تصمیم‌ها، اقدامات اصلاحی، نتایج
- پیوست‌ها: PDF، Word، Excel، تصاویر

مسئله: این آرشیو به‌صورت یکپارچه و هوشمند قابل جستجو نیست.

**سؤال اصلی:** آیا می‌توان با ابزارهای موجود و حداقل هزینه، این آرشیو را به منبعی تبدیل کرد که AI بتواند جستجو، تحلیل، گزارش‌سازی و استخراج `Lesson Learned` با قابلیت استناد انجام دهد؟

---

## ۲. رویکرد پروژه (از ساده به پیچیده)

بر اساس سند تعریف مسئله، بررسی از سطح ۱ شروع و فقط در صورت نیاز ارتقاء می‌یابد:

| سطح | شرح | وضعیت |
|-----|-----|-------|
| ۱ | استفاده مستقیم از ابزار موجود (ChatGPT/Claude روی TXT) — **Baseline** | ✅ اثبات‌شده |
| ۲ | ابزار آماده رایگان (NotebookLM و ...) | بررسی شده |
| ۳ | **اتوماسیون استخراج → متن → پاک‌سازی → دسته‌بندی** | ✅ **همین ریپو** |
| ۴ | RAG ساده (Chunking + Embedding چندزبانه + ChromaDB) | 🔜 قدم بعدی |
| ۵ | استخراج ساختاریافته `Problem→Cause→Action→Result→Lesson` | آینده |
| ۶ | GraphRAG / Agent / Fine-tuning | فقط در صورت نیاز اثبات‌شده |

**اصل ضدسوگیری:** هیچ فناوری پیش‌فرض نیست. هر افزایش پیچیدگی باید با افزایش قابل‌توجه ارزش توجیه شود.

**معیارهای مقایسه:** هزینه، سادگی، نیاز به سخت‌افزار جدید، زمان راه‌اندازی، پشتیبانی فارسی/PDF/Email، کیفیت جستجو و قابلیت استناد.

## ۳. پایپ‌لاین فعلی — `step3_discovery.py`

استخراج خودکار از Outlook → پاک‌سازی هوشمند → خروجی Markdown با متادیتا.

```
Outlook (Archives/Inbox/نصب نیرو/بویلر واحد ۳/دریافتی)
  ↓  win32com
استخراج Body + Sent/From/To/Cc/Subject + Attachments
  ↓
parse_and_clean_thread() — تفکیک thread بر اساس هدرهای From:
  ↓  per-message clean_single_message_body()
پاک‌سازی چندلایه (جزئیات پایین)
  ↓
Markdown + متادیتا در Extracted_Sample/
```

### ۳.۱ خروجی

```
Extracted_Sample/
  14031117_005_کسری پیچ و مهره...md   # هر ایمیل = یک فایل
  attachments/                         # پیوست‌های معتبر (182 MB — در گیت نادیده گرفته شده)
```

هر فایل:

```markdown
---
شناسه: 00000000C5CAE...
موضوع: RE: کسری پیچ و مهره های کیسینگ بویلر 5-6
فرستنده: Taherkhani, Ali
گیرنده اصلی (To): Vazirpanah Majid
رونوشت (Cc): ...
تاریخ شمسی: 1403/11/17
مسیر پوشه: Inbox / نصب نیرو / بویلر واحد ۳ / دریافتی
تعداد پیوست‌ها: 1
پیوست‌ها:
- attachments/14031117_005_9_...xlsx
---

# متن مکاتبه:

### 📩 آخرین پیام (پاسخ جاری):
...

### 📜 پیام در تاریخچه مکاتبات:
> From: Vazirpanah Majid
> Sent: 1403/11/16
> To: Taherkhani, Ali
> Subject: RE: ...

...
```

**۱۰۰ سند + ۱۶۶ پیوست** استخراج و پاک‌سازی شده و با چشم انسانی تأیید شده است.

## ۴. منطق پاک‌سازی — ۱۸ سناریو تست‌شده

تمام قواعد روی **۱۸ سناریو واقعی** تست و رگرسیون شده‌اند:

| لایه | قانون | مثال |
|-----|-------|------|
| **برش پایانی** | اولین `باتشکر/با تشکر/باسپاس/با سپاس` (+ `با تجدید احترام`) **از پایین** → برش تا `From:` بعدی. اگر نبود → اسکن زنجیره‌ای ۳۰ خط آخر | `با سپاس → ارسلان اکبرآبادی / 3243 :داخلی` حذف |
| **بنر امنیتی** | پاراگراف حاوی `هشدار امنیتی`، `از خارج سازمان`، `سامانه خدمات IT`، `WARNING:`، `mbe.mapnagroup.com` یا `کد رفتاری/باشگاه کتابخوانی/دامنه ایمیل` → کل پاراگراف حذف (فوروارد تو در تو هم) | بنر Outlook + کد رفتاری ۱۰۳ + اطلاعیه تغییر دامنه |
| **امضای بدون عبارت پایانی** | اسکن از پایین: نویز قوی (tel/fax/تلفن/فکس/داخلی/کدپستی/postal/www/confidential) حتی روی خطوط بلند؛ عناوین شغلی بلند ۴۵–۸۰ کاراکتر بدون نقطه‌گذاری + کلیدواژه امضا → حذف زنجیره‌ای | `6898 :داخلی`، `+98... تلفن`، `Mapna Power Plants... Co.` |
| **آدرس** | `تهران،`+`بزرگراه/بلوار/خیابان` در یک خط + `No. 13` + `office:/factory:` → قوی | `13 تهران، بزرگراه... پلاک` |
| **احوال‌پرسی** | خط کامل `با سلام/باسلام/سلام علیکم/با درود` حذف | |
| **القاب** | حلقه‌ای از ابتدای خط: `جناب/سرکار/آقای/خانم/مهندس/دکتر/همکار` (+ گرامی/محترم) با جداکننده `/،-` — با واژه‌مرز (`همکاران` نماند)؛ وسط خط `... - جناب آقای مهندس X` → `- X` | `همکار گرامی / جناب آقای مهندس طاهرخانی` → `طاهرخانی` |
| **احتراماً** | پیشوند `احتراماً[،]` از ابتدای جمله بریده، بقیه حفظ | `احتراماً، پیرو...` → `پیرو...` |
| **آرتیفکت اوت‌لوک** | `<mailto:...>`، `<user@domain>`، `<http://...>`، `[...]`, `<>`، فاصله دوتایی → پاک | |
| **Subject** | `[WARNING: ATTACHMENT UNSCANNED]` از موضوع و نام فایل حذف | |
| **تاریخ** | `Sent: Tuesday, February 4, 2025 9:57 AM` → `Sent: 1403/11/16`؛ فارسی `12 شهریور 1404` → `1404/06/12`؛ ساعت حذف | یکدست شمسی |
| **پیام خالی** | بدنه خالی پس از پالایش → `فاقد پیام متنی مهم` (محتوا در پیوست) | ایمیل حامل پیوست |

سایر: جداکننده `---`، خطوط فارسی/عربی `ي→ی` و `ك→ک` نرمال‌سازی، `ZWNJ` handling.

## ۵. اجرا

### پیش‌نیاز

- Windows + Outlook کلاسیک (MAPI) — پوشه `Archives/Inbox/نصب نیرو/بویلر واحد ۳/دریافتی`
- Python 3.10+ و `pywin32` (`pip install pywin32`)

### دستور

```bat
set PYTHONIOENCODING=utf-8
python step3_discovery.py
```

خروجی در کنار پروژه: `Extracted_Sample/` (مسیر از `__file__` ساخته می‌شود، نه Desktop).

- `MAX_LIMIT = 150` — برای کل پوشه کافی است (۱۰۰ پیام)
- پیوست‌ها فقط با پسوند مجاز و فیلتر امضا (`image/signature/logo` زیر ۴۰KB حذف)

> **نکته CMD:** خروجی فارسی فقط از طریق Python خوانده شود؛ `dir` کدپیج فارسی ندارد.
